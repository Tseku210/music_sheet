# khuur_sheet_music

Flutter package that renders sheet music on a `Canvas` and plays it back over MIDI. It is a fork of [tomoyu719/simple_sheet_music](https://github.com/tomoyu719/simple_sheet_music), maintained for the [Khuur](https://github.com/Tseku210/khuur_app) app.

## Commands

```bash
flutter pub get          # also resolves example/
flutter analyze          # library, tests, and example; must report no issues
flutter test             # the view's, the painter's and the player's tests in test/
cd packages/score_model && dart test   # score model tests (not run by flutter test)
cd packages/score_layout && dart test  # layout engine tests (not run by flutter test)
cd packages/score_layout && mkdir -p build && dart compile exe benchmark/layout_benchmark.dart -o build/layout_benchmark && build/layout_benchmark   # layout cost benchmark, compiled; exits 1 when over budget
cd packages/score_layout && dart run tool/generate_bravura.dart   # rewrites lib/src/bravura.g.dart from tool/bravura_metadata.json
cd example && flutter test   # the example app's tests (not run by the root's flutter test)
cd example && flutter run -d macos   # the example app
```

## Layout

- `lib/khuur_sheet_music.dart` is the public export list. It exports all of `score_model`, the `score_layout` types it names, and the shell in `lib/src/`. Anything not exported there is internal.
- `packages/score_model/` is the pure-Dart score model, a pub workspace member. Its design and the deviations accepted while implementing it are in `docs/design/score-model/RATIONALE.md`.
- `packages/score_layout/` is the pure-Dart layout engine, a pub workspace member. Its design and the deviations accepted in each unit are in `docs/design/layout/RATIONALE.md`. `SheetLayout` is its entry point. Its glyph table `lib/src/bravura.g.dart` is generated by `dart run tool/generate_bravura.dart` from `tool/bravura_metadata.json`. `benchmark/layout_benchmark.dart` is the layout cost gate, and every change to the engine reruns it.
- `lib/src/sheet_view.dart` holds `SheetView` and `SheetController`. The view shows a `Score` as a scrolling list of system tiles over `SheetLayout`, drawn by the one painter in `lib/src/painting.dart`, measured by `lib/src/paragraph_measurer.dart` and coloured by `lib/src/sheet_palette.dart`. The painter draws glyphs as text in `fonts/Bravura.otf` (licence in `fonts/OFL.txt`).
- `lib/src/score_player.dart` holds `ScorePlayer`. It plays a `score_model` playback script from one script clock through the `MidiOutput` seam of `lib/src/midi_output.dart`. The adapter there sends to `flutter_midi_pro` (Android, iOS, macOS only) and loads the `SoundFont` (`lib/src/sound_font.dart`) that the app passes in.
- `test/mock/` holds hand-written fakes, `fake_midi_output.dart` and `fake_wall_time.dart`. Tests do not use a mocking package. `test/support/` holds the helpers that draw and write pictures.
- `example/lib/main.dart` is the example app, one page over `SheetView` and `ScorePlayer`. `example/lib/demo_score.dart` builds its tune. `example/test/` tests both and imports the root's `test/mock/` and `test/support/` by relative path.

## Conventions

- Lints come from `pedantic_mono`. Keep `flutter analyze` clean.
- Asset paths that code loads at runtime must use the `packages/khuur_sheet_music/` prefix. A bare `fonts/...` or `assets/...` path only resolves inside this package, not in a consuming app.
- The package bundles no SoundFont, because Flutter ships every package asset to every consuming app. The example app bundles `example/assets/soundfonts/piano.sf2`, FreePats' CC0 Upright Piano KW (small).
- Commit messages use Conventional Commits: `type(scope): description`.
- The library is open source and stays general. Khuur is its first consumer, not its target, so nothing Khuur-specific goes in `lib/` or `packages/`. Instruments, marks and examples are general, and Khuur's designs guide scope without being requirements.
